## `core/v0.9.0` - 2026-10-20

### Changed

- feat(core)!: replace the stringly-typed assembly protocol with a typed one, so a deployment is type-checked before anything is constructed. `resource.Factory` is generic (`New` returns the value's own type), the registry keeps that type as the entry's build type, and a dependency is declared and read through one handle (`resource.Require[tool.Source]("tool")` contributes the `Spec` requirement and reads the value), with `Input.deps` unexported so a factory can only read what it declared; `Register` is a free function because Go has no generic methods. `deploy.Plan` is a new pure phase: it resolves every kind, validates supplied and required deps, checks the DAG, and checks every edge's Go type — a factory's build type, a container's declared item type or an external's injected type against the consumer's requirement — including agent engine and hook sockets and the secret-store socket the assembler itself requires, reporting every dependency edge together and naming the resource and dep; `Plan.Build` then only constructs, `Builder.Build` is Plan plus Build, and `Builder.Deploy` adds Wire. Reads are typed (`deploy.Resolve`, `Collect`, `CollectNamed`) and internal wiring moved off `Result.Value`, which stays as the dynamic accessor for host-level discovery where the resource name comes from configuration. `resource.DeploymentBinder(any)` becomes `deploy.Binder` over a typed `deploy.View` (a stale untyped implementation is now a loud error instead of a silent skip), and injected externals carry their Go type via `deploy.NewExternal`/`runtime.NewExternal`, so a mismatched injection is a startup error. Removed: `DepSpec`, `Input.Dep`/`DepsMany`, `validateDeps`, `validateExternalContracts`. Fixed along the way: the memory hooks declared no dependency while reading one, so the assembly could never be supplied through a document (`memory/context` and `memory/turn` now declare it); the delegation directory stopped satisfying the binder contract and silently never bound; a typed read names the concrete dep key (`unit.a`, not `unit`) and distinguishes nil from a typed nil; `Spec.DepSpecFor` resolves an exact dep name before a `Many` prefix, so a spec declaring both `tool` and `tool.x` no longer checks `tool.x` against the wrong contract; `Specs()` clones so a caller cannot mutate a registered factory. A migration guide is in `docs/migrations/core-v0.9.0.md`.

## `core/v0.8.1` - 2026-10-20

### Changed

- feat(core/sandbox): declare a session's input surface up front so fd 0 stays /dev/null — a non-TTY session always took a stdin pipe, so a child that branches on what fd 0 is read that pipe whether or not anyone would ever write to it (`rg pattern` with no path operand searched the stream instead of the working tree, `cat` blocked, `test -p /dev/fd/0` answered true), and `ExecOptions.Stdin`'s own doc — nil means no stdin — was not implemented by `StartSession`; `SessionSpec.Stdin` is now the only declaration: with TTY false it decides the spawn (true gets a pipe, false leaves cmd.Stdin nil so os/exec hands the child /dev/null), it is ignored for TTY where the pty master is always writable, and `Start` still never delivers `Opts.Stdin`, those bytes no longer counting as a declaration either, so a non-TTY spec carrying them without `Stdin` keeps fd 0 on /dev/null and `Write` reports NotAvailable; `Exec` is unaffected because it sets `spec.Stdin` itself before `Start` and then writes and closes, and `ExecOptions.Stdin` nil or empty both mean no input, an empty slice no longer buying the child a pipe; `SessionCapabilities.Stdin` joins TTY/Signal/Events so a caller can ask before trying, `Write` on a session that declared no input returns errdefs.NotAvailable ("session started without stdin; set SessionSpec.Stdin to stream input") instead of the ErrSessionClosed it used to return, because that is a capability the spec never asked for rather than a handle that went away, and `CloseInput` on such a session stays a no-op success so `Exec` keeps calling it unconditionally; `ExecRequest.Stdin` gives the approver the same view — `Stdin || TTY` for Start, a non-empty `ExecOptions.Stdin` for Exec — so a predicate can gate on "this command channel carries caller input"; the unix `localSession` and the windows `winSession` follow the same rules (skip `StdinPipe()` when nothing declared input, remember the decision in an `input` field for `Write`/`CloseInput`/`Capabilities`, TTY paths reporting `Stdin: true`), and `Write` snapshots `stdin` under the lock instead of reading the field from the copy goroutine that `CloseInput`/`Close` nil out concurrently, which was a data race. The tests probe the child's actual fd 0 (`test -p /dev/fd/0`, falling back to /proc/self/fd/0) rather than asking whether a write succeeded: the never-ending empty pipe, `Stdin: []byte{}` buying no pipe, declared bytes still arriving through one, the session side (declared vs undeclared, NotAvailable vs ErrSessionClosed, a TTY `CloseInput` staying NotAvailable), the approver's view, and the Windows pipe backend; the merge path that never touches Runner.Exec is pinned by decorator tests, where `WithDefaults`' Stdin fallback buys no pipe and a `cat` session has to exit on its own. feat(core/delegation): give a delegated run a declared policy channel — a delegated run gets its own session identity, so a deployment that resolves execution policy per session (sandbox mode, think level, model hint) had no way to say which policy a subagent runs under: the caller's run attributes do not reach it and `Request.Metadata` is graph input, so the subagent landed on the store's default tier and every gated command failed closed from inside a run the caller cannot inspect; `Request.Attributes` carries caller-declared run attributes onto the subagent's `Run.Attributes` via `agent.Request`, which core treats as opaque, with lineage service-owned — the service's own keys are layered over the declared ones so a delegation cannot be made to look like a different tool call, and declaring `tool.call_id` is a validation error rather than a silent override, since without an ambient call id to layer over a caller-chosen value would reach `Run.Attributes` and be stamped onto every envelope as delegation lineage — the caller's own run attributes never inherited, because deployments keep run-scoped payloads there (checkpoint recovery blobs, for instance) that must not surface inside a subagent, and the map joining identity: idempotency compares it verbatim so replaying a key under a different policy is a conflict instead of a silent reuse of the earlier (possibly wider) decision, while resume identity excludes the lineage keys because a retry is a new tool call and must still replay the parked run; nil and an empty map are equivalent, an empty value is allowed and distinct from an absent key, and blank keys plus surrounding whitespace in a key or value are validation errors because the map is compared verbatim; `WithSessionInitializer` registers a `SessionInitializer` that runs once per delegated run, after the session identity is minted and before the turn starts or resumes, which is where a deployment writes the per-session state core does not model into its own store — failing closed when the hook errors rather than running under a wider default, running on the manager-less path too wherever a `SessionProvider` minted the identity, and refusing the delegation with a validation error when it has no identity at all instead of proceeding under the store's default, so configuration that could apply its policy is unaffected while the combination that silently ran unconfined now refuses; a nil option is rejected; `delegation.WithRunAttributes` is the producer for the context-stamped channel (copy-on-write, a nil or empty map clearing an outer stamp) and the `delegate` tool copies what it carries onto every `Request` it builds, so middleware — the last seam that still sees the caller's context — is the only way in and model arguments can never widen a policy, which the tool description now says outright; a host wired from a deployment document injects both through `delegation.NewServiceFactory(opts…)`, `cloneRequest` copies the map, and the JSON contract is pinned (the `attributes` field name, omitted when empty, and the round trip); deployments that use neither seam see no behavior change, and docs/guides/sandbox.md plus docs/guides/delegation.md document both seams, which one reaches a session-keyed store, and that approval is not inherited.
